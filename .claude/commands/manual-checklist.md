# 수동 검증 체크리스트 생성 커맨드

$ARGUMENTS 기획서를 기준으로 운영자 수동 검증 체크리스트를 생성합니다.

> **목적:** AI/Playwright 자동 검증 이후, 실 운영 환경에서 운영자가 화면을 직접 조작하며 검증하는 단계용. 자동 검증으로는 잡히지 않는 UX/UI/회계 로직/실 데이터 회귀를 인간이 최종 확인.

## 사용 예시

| 패턴 | 의미 |
|------|------|
| `/manual-checklist {기획서_경로}` | 단일 기획서 기반 |
| `/manual-checklist {기획서_경로} {테마_식별자}` | 기획서 + 적용 테마 명시 |
| `/manual-checklist {기획서_경로} {SKILL_경로}` | 기획서 + SKILL 문서 교차 |
| `/manual-checklist {기획서_경로} {commit_hash}` | 특정 commit 의 변경분 기준 |

**예:**
- `/manual-checklist SKILL/refs/0427_planning/C. 접수 관리-1.pdf 테마21`
- `/manual-checklist docs/spec/payment_v2.pdf api/payment/`
- `/manual-checklist 기획서.md HEAD~3..HEAD`

## 입력 우선순위

1. **기획서 원문** (PDF / 이미지 / MD / 노션 / Figma description) — 1차 진실의 소스
2. **SKILL/명세서** — 결정 픽스 + 영향 매트릭스 (있으면)
3. **DECISIONS_LOG** — 옵션 선택 사유 (있으면)
4. **변경 commit / 마이그레이션 SQL** — 실제 적용 범위
5. **자동 검증 결과** (Playwright/QA 보고서) — 이미 통과한 항목 표시

기획서가 누락되면 작업 중단하고 사용자에게 질문:
> "검증할 기획서를 지정해 주세요. 기획서 없이 체크리스트를 만들면 누락이 발생합니다."

## 산출물 위치 (반드시 준수)

| 산출물 | 위치 | 파일명 | 비고 |
|--------|------|--------|------|
| 수동 체크리스트 | `QA/` | `manual_checklist_YYYYMMDD_v#_{주제}.md` | 운영자 인쇄/체크용 |
| QA 인덱스 갱신 | `QA/index.md` | 해당 행 추가 | 진행도 추적 |

`QA/index.md` 가 없으면 먼저 생성.

## 체크리스트 작성 절차

### Step 0. 기획서 항목 추출 (Description 1:1 매칭)
기획서 Description (또는 상세 요구사항) 의 **모든 번호 항목**을 누락 없이 추출. 임의 요약/축약 금지. PDF에 "*" 마커가 붙은 강조 항목은 별도 표기.

추출 결과를 SKILL 명세서의 변경사항 매트릭스와 교차 확인:
- 기획서에 있으나 SKILL/코드에 없는 항목 → **누락 경고** + 체크리스트에 "❌ 미반영 확인 필요" 로 표기
- SKILL/코드에 있으나 기획서에 없는 항목 → "(SKILL 자체 결정)" 표기

### Step 1. 로직 위험 지점 자동 도출
변경 commit / SKILL 영향 매트릭스 / DB SQL 을 분석해 아래 카테고리 중 해당하는 것만 자동 포함 (해당 없으면 생략):

**B-1. DB 마이그레이션**
- [ ] ALTER 적용 후 SHOW COLUMNS 결과 일치
- [ ] RENAME 후 잔여 옛 컬럼명 grep 0건 (`grep -rn "{old_col_name}" pages/ api/ lib/ cron/`)
- [ ] NULL 디폴트 검증 — 기존 행 영향 없음
- [ ] 인덱스/외래키 영향 (CHANGE COLUMN 시 키 보존)
- [ ] 운영 트래픽 시점 락 영향 (큰 테이블)
- [ ] rollback SQL 동작 검증

**B-2. 캐스팅 / 데이터 변환**
- [ ] VARCHAR ↔ INT 변환 안전성 (빈문자 → 0, 비숫자 → 0)
- [ ] 날짜 포맷 변환 (YYYYMMDD ↔ YYYY-MM-DD)
- [ ] NULL vs 빈문자 vs 0 일관성
- [ ] 음수/0/매우 큰 값 처리

**B-3. 트랜잭션 / 동시성**
- [ ] 부분 실패 시 일관성 (rollback)
- [ ] DB 락 / Race Condition 회피
- [ ] 동일 사용자 동시 요청 처리

**B-4. 권한 / 인증**
- [ ] mt_level 별 접근 가능/차단 매트릭스
- [ ] 본인/소속 데이터만 조회 (lv7/8)
- [ ] 잠금 상태 (정산완료 등) 에서 저장 차단
- [ ] 서버 측 권한 재검증 (클라이언트만 의존 금지)

**B-5. 정산 / 회계 로직**
- [ ] 합계 계산 순서 (차감 vs 가산)
- [ ] 중복 차감 방지 (같은 항목 두 번 INSERT?)
- [ ] 스냅샷 vs LIVE 분기 (`completed` vs `pending`)
- [ ] 카테고리별 분기 (cat_idx) 누락 없음

**B-6. 폼 / JS 변경**
- [ ] 라벨/JS class/JS 변수명 변경 후 잔여 참조 0건
- [ ] 캐시 무효화 (filemtime, hash, 강제 새로고침)
- [ ] 클라이언트 + 서버 이중 검증
- [ ] 폼 reset / 복사 모드 회귀

**B-7. 엣지케이스**
- [ ] 0 / NULL / 공백 / 매우 긴 문자열
- [ ] 한글 / 특수문자 / 이모지
- [ ] 이메일/전화번호/계좌번호 형식
- [ ] 동시 다건 처리 (배열 입력)

**B-8. 보안**
- [ ] SQL Injection (파라미터 바인딩)
- [ ] XSS (출력 이스케이프)
- [ ] CSRF 토큰 검증
- [ ] 파일 업로드 확장자/MIME 검증

**B-9. 회귀 (기존 데이터)**
- [ ] 마이그레이션 전 기존 데이터 표시 정상
- [ ] 미완료 접수 LIVE 재계산 동작
- [ ] 완료 접수 스냅샷 보존 (변경 영향 없음)
- [ ] 엑셀 다운로드 컬럼 정합성

**B-10. 외부 연동 / 메시지**
- [ ] 메일 발송 / SMS / 카카오 알림
- [ ] 외부 API 호출 (실패 시 fallback)
- [ ] 크론/배치 영향

> 위 카테고리는 최소 set. 변경 성격에 따라 자동으로 추가 (예: 파일 업로드 작업이면 파일 검증 카테고리 추가).

### Step 2. 자동 검증 통과 항목 마킹
이미 Playwright/AI 자동 검증으로 통과한 항목은 체크리스트에서 `🤖 자동검증 통과` 로 표시하고, 운영자는 **확인만** 하면 되도록 분리. 운영자 시간 절약.

### Step 3. 우선순위 분류
- 🔥 **CRITICAL** — 실패 시 데이터 손상/회계 오차 가능
- ⭐ **HIGH** — 실패 시 기능 동작 안 됨
- 🔍 **MEDIUM** — UX 문제 가능
- 💬 **LOW** — 단순 표기/문구

### Step 4. 검증 환경 명시
- 검증 계정 (어떤 mt_level로 로그인?)
- 검증 데이터 (어떤 접수 idx? 어떤 정산 idx?)
- 검증 URL (운영/스테이징/로컬?)
- 사전 조건 (예: 정산 완료 접수가 있어야 함)

## 작성 시 금지 사항

- [ ] 기획서에 없는 임의 요구사항 추가 (SKILL 자체 결정은 "(SKILL)" 표기)
- [ ] 추측성 검증 항목 (예: "혹시 모를 케이스") — 근거 없는 항목은 노이즈
- [ ] 자동 검증으로 충분히 검증되는 항목을 수동에 중복 — 운영자 시간 낭비
- [ ] CHECKlist 항목에 "잘 동작하는지 확인" 같은 모호한 표현 — 구체적 행위/기대값 필수
- [ ] 기존 자동 검증 보고서 (Playwright) 를 다시 적지 말고 **참조 링크만**

## 후속 작업

체크리스트 작성 직후:
1. `QA/index.md` 에 행 추가 (`| YYYY-MM-DD | manual_checklist_*.md | 수동 체크리스트 | ⬜ 운영자 검증 대기 |`)
2. 사용자에게 검증 시작 안내 (3~5문장)
3. 운영자 검증 완료 후 다시 호출하면 § E 이슈를 SKILL/CHANGE/QA 보고서로 반영
