# 수동 검증 체크리스트 생성 커맨드

$ARGUMENTS 기획서 + SKILL 명세서를 기준으로 운영자 수동 검증 체크리스트를 생성합니다.

> **목적:** AI/Playwright 자동 검증 이후, 실 운영 환경에서 운영자가 화면을 직접 조작하며 검증하는 단계용. 자동 검증으로는 잡히지 않는 UX/UI/회계 로직/실 데이터 회귀를 인간이 최종 확인.
>
> **핵심 가설:** SKILL 문서가 완전하면 (변경 매트릭스 + 결정 픽스 + 영향 영역 + 진행 이력 모두 누적) 기존 체크리스트를 참조하지 않아도 동일 검증 범위를 자동 재구성 가능. → SKILL 의 완전성 자체를 검증하는 메타-도구이기도 함.

## 사용 예시

| 패턴 | 의미 |
|------|------|
| `/manual-checklist {기획서_경로} {테마_식별자}` | 기획서 + 단일 테마 SKILL |
| `/manual-checklist {기획서_경로} {테마1} {테마2} ...` | 기획서 + 다중 테마 누적 (이전 변경분 통합) |
| `/manual-checklist {SKILL_경로}` | 기획서가 SKILL 내부에 명시되어 있을 때 SKILL 단독 입력 |
| `/manual-checklist {기획서_경로} --auto-transitive` | SKILL 의 "연결 테마" 를 transitive 자동 추적 |

**예:**
- `/manual-checklist SKILL/refs/0427_planning/C. 접수 관리-1.pdf 테마21 테마28 테마29 테마31`
- `/manual-checklist SKILL/REFACTOR_0427/21_REGISTRATION_FORM_REVAMP.md --auto-transitive`

## 입력 우선순위 (재정의)

**기획서와 SKILL 둘 다 1차 진실의 소스.** 둘이 충돌하면 → DECISIONS_LOG 의 최신 결정 우선 → 그것도 없으면 사용자에게 질문.

| # | 입력 | 역할 | 누락 시 |
|---|------|------|--------|
| 1 | **기획서 원문** (PDF/이미지/MD/Figma) | 외부 요구사항 1:1 추출 | 작업 중단, 사용자 질문 |
| 2 | **SKILL 명세서들** (단일 또는 다중) | 변경 매트릭스 + 결정 픽스 + 영향 영역 + 진행 이력 | SKILL 자체가 부실하다는 신호 — 사용자에게 알리고 SKILL 보강 우선 권장 |
| 3 | **DECISIONS_LOG** | 옵션 답변 + 사유 — 충돌 해소 | 결정 중복 우려 시 사용자 질문 |
| 4 | **변경 commit / 마이그레이션 SQL / 자동 검증 결과** | 실제 적용 영역 + 통과 항목 마킹 | 자동검증 통과 마킹만 생략, 본 작업은 진행 |

### 🚫 의도적 배제

**기존(이전 버전) 수동 체크리스트는 참조하지 않는다.** 사유:
- SKILL 이 완전하다는 전제로 운영. 기존 체크리스트에만 있고 SKILL 에 없는 항목 = SKILL 불완전 신호 → SKILL 보강이 우선
- 기존 체크리스트 참조는 누적 의존성을 만들어 SKILL 의 단일 진실 원칙을 깸
- 단, **새로 생성된 체크리스트가 기존 영역을 빠뜨리는지 사용자가 직접 비교 가능** — 그것이 SKILL 완전성 회귀 검증 방법

기존 체크리스트는 운영자 진행 이력 기록용으로만 유지하거나 삭제 가능.

기획서가 누락되면 작업 중단하고 사용자에게 질문:
> "검증할 기획서를 지정해 주세요. 기획서 없이 체크리스트를 만들면 누락이 발생합니다."

SKILL 이 누락되면 사용자에게 알림:
> "본 작업 영역의 SKILL 명세서 경로를 지정해 주세요. SKILL 이 없으면 자동검증 통과 항목 / 결정 픽스 / 영향 영역 추출이 불가능해 체크리스트 품질이 떨어집니다."

## 산출물 위치

| 산출물 | 위치 | 파일명 | 비고 |
|--------|------|--------|------|
| 수동 체크리스트 | `QA/` | `manual_checklist_YYYYMMDD_v#_{주제}.md` 또는 프로젝트 규칙 우선 | 프로젝트 명명 규칙 검증 통과해야 함 |
| QA 인덱스 갱신 | `QA/index.md` | 해당 행 추가 | 진행도 추적 |

> **프로젝트 명명 규칙 우선:** 프로젝트가 `qa_YYYYMMDD_v#_*.md` 같은 자체 규칙을 가지면 그것을 따른다. `QA/index.md` 또는 `scripts/validate-qa-naming.sh` 확인.

`QA/index.md` 가 없으면 먼저 생성.

## 체크리스트 작성 절차

### Step 0. 입력 자료 수집
- 기획서 원문 read
- 지정된 SKILL 명세서들 read (다중이면 모두)
- `--auto-transitive` 옵션이면 각 SKILL 의 "연결 테마" / "Connected" / "see also" 섹션을 따라가 transitive 추가 read (사이클 차단)
- DECISIONS_LOG / CHANGE_LOG / progress.md 자동 탐색하여 read
- 자동 검증 보고서 (`QA/qa_*_v*.md` 중 본 영역 다룬 것) 자동 탐색하여 통과 항목 매핑

### Step 1. 기획서 항목 추출 (Description 1:1) — 🔥 절대 누락 금지

**기획서 Description 은 단 1개도 빠뜨리지 않는다.** 본 커맨드의 최우선 강제 원칙.

- 기획서 Description 의 **모든 번호 항목**을 누락 없이 1:1 추출. 임의 요약/축약/통합 금지
- "*" 강조 항목 별도 표기
- **자동검증으로 이미 통과한 항목이라도 체크리스트의 A 섹션에는 반드시 등재** (운영자가 한 번 더 시각 확인 가능하도록). 자동검증 통과 항목은 `🤖 자동검증 통과` 마크만 부착, 등재 자체는 생략 금지
- **SKILL 에만 있고 기획서에 없는 항목**은 B 섹션 (SKILL 변경 매트릭스) 에만 등재. A 섹션에 섞지 않음
- **기획서에 있으나 SKILL/코드에 없는 항목** → A 섹션에 `❌ SKILL 미반영` 강조 표기 + 사용자 보고

각 A 행에 다음 메타를 명시:
- 출처: (기획서 페이지/섹션)
- SKILL 매핑: (SKILL 21 #N / 28 #M / 없음)
- 결정 ID: (DECISIONS_LOG 답변값)
- 자동검증: (qa_*.md PASS / 없음)

체크리스트 작성 끝에 § H SKILL 완전성 진단에서 **"기획서 항목 SKILL 누락 = N건"** 을 명시. 0건이 아니면 SKILL 보강 우선 권장.

### Step 2. SKILL 변경 매트릭스 통합 추출 ⭐ (핵심)
다중 SKILL 입력 시 각 SKILL 의 **§ 변경사항 매트릭스 / § 영향 매트릭스 / § Phase / § 결정 진행 상태** 표를 모두 추출하고 중복 제거 후 통합. 누락 없이 행 단위 누적.

각 행마다 다음 메타 자동 첨부:
- 출처 SKILL (어느 명세서에서 왔는지)
- 결정 ID (DECISIONS_LOG 에 답변 있으면 답변값 포함)
- 자동검증 통과 여부 (자동 검증 보고서 매핑)

### Step 3. 로직 위험 지점 자동 도출
변경 commit / SKILL 영향 매트릭스 / DB SQL / DECISIONS_LOG 충돌 사례 등을 분석해 아래 카테고리 중 해당하는 것만 자동 포함 (해당 없으면 생략):

> **결과 표기 규칙 (체크리스트 전체 공통):**
> 각 행 끝에 **결과 컬럼** 을 두고 운영자가 채운다.
> - `✅` 통과 / `❌` 실패 / `⚠️` 이상 발견 / `⬜` 미진행
> - `🤖` 자동검증 통과 (운영자 확인만)
>
> **체크박스 `[ ]` 양식을 사용하지 않는다.** 표 컬럼의 결과 칸이 빈 값(⬜) 일 때 = 미진행.

**B-1. DB 마이그레이션**
- ALTER 적용 후 SHOW COLUMNS 결과 일치
- RENAME 후 잔여 옛 컬럼명 grep 0건
- NULL 디폴트 검증 — 기존 행 영향 없음
- 인덱스/외래키 영향 (CHANGE COLUMN 시 키 보존)
- 운영 트래픽 시점 락 영향 (큰 테이블)
- rollback SQL 동작 검증

**B-2. 캐스팅 / 데이터 변환**
- VARCHAR ↔ INT 변환 안전성 (빈문자 → 0, 비숫자 → 0)
- 날짜 포맷 변환 (YYYYMMDD ↔ YYYY-MM-DD)
- NULL vs 빈문자 vs 0 일관성
- 음수/0/매우 큰 값 처리

**B-3. 트랜잭션 / 동시성**
- 부분 실패 시 일관성 (rollback)
- DB 락 / Race Condition 회피
- 동일 사용자 동시 요청 처리

**B-4. 권한 / 인증**
- 회원 레벨 별 접근 가능/차단 매트릭스
- 본인/소속 데이터만 조회
- 잠금 상태 (정산완료 등) 에서 저장 차단
- 서버 측 권한 재검증 (클라이언트만 의존 금지)

**B-5. 정산 / 회계 로직**
- 합계 계산 순서 (차감 vs 가산)
- 중복 차감 방지
- 스냅샷 vs LIVE 분기
- 카테고리별 분기 누락 없음

**B-6. 폼 / JS 변경**
- 라벨/JS class/JS 변수명 변경 후 잔여 참조 0건
- 캐시 무효화 (filemtime, hash, 강제 새로고침)
- 클라이언트 + 서버 이중 검증
- 폼 reset / 복사 모드 회귀

**B-7. 엣지케이스**
- 0 / NULL / 공백 / 매우 긴 문자열
- 한글 / 특수문자 / 이모지
- 이메일/전화번호/계좌번호 형식
- 동시 다건 처리 (배열 입력)

**B-8. 보안**
- SQL Injection (파라미터 바인딩)
- XSS (출력 이스케이프)
- CSRF 토큰 검증
- 파일 업로드 확장자/MIME 검증

**B-9. 회귀 (기존 데이터)**
- 마이그레이션 전 기존 데이터 표시 정상
- 미완료 트랜잭션 LIVE 재계산 동작
- 완료 트랜잭션 스냅샷 보존 (변경 영향 없음)
- 엑셀 다운로드 컬럼 정합성

**B-10. UI 밀도 / 반응형 / 시각 회귀**
- 1199 / 1366 / 1920px 해상도별 깨짐 없음
- 모바일/태블릿 breakpoint 폴백
- 텍스트 줄바꿈/오버플로우
- 셀 겹침 / 라벨-입력 정렬

**B-11. 외부 연동 / 알림**
- 메일 발송 / SMS / 카카오 알림
- 외부 API 호출 (실패 시 fallback)
- 크론/배치 영향

**B-12. 글로벌 회귀 (다른 페이지 / 공통 모듈 영향)**
- 변경된 공통 모듈 (daum postcode, jalert, common.js 등) 사용처 회귀
- 공통 클래스 (add_flex / wd_25 / grid-4col 등) 사용 페이지 영향

> 카테고리는 최소 set. 변경 성격에 따라 자동 추가 (예: 파일 업로드 작업이면 파일 검증 카테고리 추가).

### Step 4. 자동 검증 통과 항목 마킹
이미 Playwright/AI 자동 검증으로 통과한 항목은 체크리스트에서 `🤖 자동검증 통과 — qa_*.md` 로 표시. 운영자는 **확인만**.

### Step 5. 우선순위 분류
- 🔥 **CRITICAL** — 실패 시 데이터 손상/회계 오차 가능
- ⭐ **HIGH** — 실패 시 기능 동작 안 됨
- 🔍 **MEDIUM** — UX 문제 가능
- 💬 **LOW** — 단순 표기/문구

### Step 6. 검증 환경 명시
- 검증 계정 (회원 레벨)
- 검증 데이터 (idx)
- 검증 URL
- 사전 조건

### Step 6.5. 자체완결성 (필수)

**체크리스트의 각 행은 다른 문서(SKILL/코드/마커명) 를 참조하지 않고 본문만으로 검증 가능해야 한다.** 외부 참조가 필요하면 그 내용을 행 안에 풀어 적는다.

### Step 7. SKILL 완전성 자체-진단
체크리스트 작성 결과 다음을 사용자 보고서 마지막에 출력:

```
## SKILL 완전성 진단
| 점검 | 결과 |
|------|------|
| 기획서 항목 SKILL 누락 | N건 |
| SKILL 결정 ID 답변 미픽스 | N건 |
| 자동검증 매핑 안 된 변경 영역 | N건 |
| transitive SKILL 누락 의심 | N건 |
```

이 진단 결과가 있으면 사용자가 "체크리스트가 부실한 게 아니라 SKILL 이 부실해서 그렇다" 를 판별 가능.
