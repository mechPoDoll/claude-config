# 작업 진행상황 고객 공유본 생성 커맨드 (소스 무관 · 모듈화)

$ARGUMENTS 기준으로 비개발자(고객) 친화 톤의 진행상황 공유본을 만든다.
**워크로그가 없어도 동작한다** — 세션 맥락 / 임의 레퍼런스 / git 이력 중 가용한 것으로 생성한다.

> 포맷·테마매핑·저장 규칙은 공통 모듈 [`_shared/customer-report-format.md`](_shared/customer-report-format.md) 가 단일 출처(SSOT)다.
> 이 커맨드는 **소스를 정규화**해서 그 모듈에 넘기는 역할만 한다.

> **사용 예시:**
> - `/share-worklog` — 오늘 날짜, 소스 자동 탐색
> - `/share-worklog 어제` — 자연어 날짜
> - `/share-worklog 2026-05-06` — 특정 날짜 (워크로그 우선)
> - `/share-worklog --ref ./notes.md` — 임의 파일을 레퍼런스로
> - `/share-worklog --ref session` — 현재 세션 대화 내용을 레퍼런스로
> - `/share-worklog --ref "git:2026-05-19"` — 해당일 git 이력만으로
> - `/share-worklog 오늘 --ref session` — 날짜 + 세션 소스 동시 지정

## 동작 절차

### Step 1. 인자 파싱
- 날짜 토큰: 비어있으면 `date +%Y-%m-%d`(오늘). "어제/오늘/그저께" 자연어 변환. `YYYY-MM-DD` 면 그대로. → `$DATE`
- `--ref <소스>` 토큰(선택): 명시 레퍼런스. 형태:
  - 파일/디렉터리 경로 → 그 내용을 읽어 소스로
  - `session` → 현재 세션의 대화·작업 맥락을 소스로 (이번 대화에서 수행/보고한 작업)
  - `git:<날짜|범위>` → 해당 git 이력만 소스로
  - 그 외 문자열 → 사용자가 붙여넣은 레퍼런스 텍스트 자체로 간주
- 오전/오후 토큰이 있으면 `meta.ampm` 에 반영 (없으면 항목 시간으로 추정)

### Step 2. 소스 해석 (우선순위 — 워크로그 선택적)

아래 순서로 **가용한 첫 소스**를 채택한다. 워크로그는 그중 하나일 뿐 필수가 아니다.

1. **명시 `--ref`** 가 있으면 그것을 1차 소스로 사용
2. **워크로그**: `worklog/$DATE.md` 가 있으면 각 항목의 "### 작업 요약" + 시간/카테고리/카운터 파싱
3. **폴백 (워크로그 없음 / `--ref session`)**: 현재 세션 대화 맥락에서 이번 기간 수행·보고한 작업을 항목화
4. **git 보강 (항상 병행)**:
   ```bash
   git log --since="$DATE 00:00" --until="$DATE 23:59" --pretty=format:"%h | %ci | %s"
   git log --since="$DATE 00:00" --until="$DATE 23:59" --name-only --pretty=format: | sort -u | grep -v '^$'
   ```
   - 자동 커밋(`*(auto):`)은 제목만 참고, 사람 손 커밋 제목은 그대로 신뢰
   - 변경 파일 영역 그룹화: `api/lib/pages/assets/layouts`→"운영 시스템", `cron/`→"자동 작업", `sql/`→"DB 변경", `skill/QA`→"문서/계획", `scripts/.claude/CLAUDE.md`→"내부 도구/설정", `worklog/`→집계 제외
5. git 도 없고(레포 아님) 소스도 비면 → 세션 맥락만으로 생성. 그래도 비면 "해당 기간 작업 내역이 없습니다." 출력 후 종료

> 핵심: 워크로그 파일이 존재하지 않아도 2번을 건너뛰고 3·4번으로 정상 생성된다.

### Step 3. 정규화

채택 소스를 공통 모듈 입력 계약 형태(`{time, summary, areas}[] + meta`)로 변환한다.
- `meta.source` 에 실제 사용한 소스 종류 기록 (worklog / session / ref:<설명>)
- 요약이 비면 커밋 제목 + 변경 영역으로 의미 복원

### Step 4. 공통 모듈 적용

[`_shared/customer-report-format.md`](_shared/customer-report-format.md) 의
Step A(테마/진행도 매핑) → B(비개발자 톤) → C(출력 형식) → D(저장+출력) 를 **그대로 따른다.**
해당 모듈이 단일 출처이므로 포맷/원칙을 여기서 중복 기술하지 않는다.

## 주의사항

- 본 커맨드의 책임은 **소스 정규화**까지. 톤/형식/저장은 공통 모듈이 결정한다.
- `--ref session` 은 워크로그가 아직 안 쌓인 진행 중 시점에 특히 유용 (방금 한 작업을 바로 공유).
- 레퍼런스가 기술 메모여도 출력은 반드시 비개발자 톤으로 변환 (원문 그대로 붙여넣기 금지).
- 공통 모듈 규칙(이모지 금지, 마크다운 헤더 금지, `■` 글머리표, 식별자 비노출)을 위반하지 말 것.
