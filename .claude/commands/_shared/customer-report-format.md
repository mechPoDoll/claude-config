# 공통 모듈 — 고객 공유본 포맷 사양 (customer-report-format)

> 이 파일은 슬래시 커맨드가 아니다. `share-worklog` 등 공유본 생성 커맨드가
> "정규화된 작업 항목 목록"을 만든 뒤 **이 사양을 그대로 적용**한다.
> 소스(워크로그 / 세션 / 임의 레퍼런스)가 무엇이든 이 모듈부터는 동일하게 동작한다.

---

## 입력 계약 (호출 커맨드가 보장)

호출 커맨드는 아래 형태의 **정규화된 작업 항목 목록**을 만들어 이 모듈에 넘긴다:

```
[
  { time: "HH:MM"|null, summary: "작업 요약(원문/세션/커밋 기반)", areas: ["api/","skill/", ...]|[] },
  ...
]
+ meta: { date: "YYYY-MM-DD", ampm: "오전"|"오후"|null, source: "worklog|session|ref:<설명>" }
```

- `summary` 가 비어 있어도 `areas` + 커밋 제목으로 의미를 복원해 채운다.
- 항목이 0개면 "해당 기간 작업 내역이 없습니다." 출력 후 종료.

---

## Step A. 테마 / 진행도 매핑

각 항목을 **REFACTOR_0427 테마 또는 별도 작업 트랙**에 매핑한다.

1. `skill/REFACTOR_0427/27_PROGRESS_PLAN.md` 의 `§ 2 테마별 일정 표`에서 진행도/일정 추출
   - 해당 파일이 없는 프로젝트면 이 단계는 생략하고 테마명만 일반 명칭으로 표기
2. 매핑 근거: 변경 파일 경로 + 작업 요약 텍스트 + `REFACTOR_0427/NN` 마커 + 해당 테마 SKILL 의 영향 파일
3. 진행도 우선순위: PROGRESS_PLAN `§2` 상태 컬럼 → 해당 SKILL `진행 상태` 체크박스 카운트
4. 일정: PROGRESS_PLAN `§2` "완료 예정" 컬럼, 없으면 생략
5. 어느 테마에도 안 맞거나 여러 테마에 걸치면 **"기타 개선 및 안정화"** 로 묶는다 (임의 테마 추정 금지)
6. 진행도가 갱신 안 된 경우 PROGRESS_PLAN 상태값을 그대로 사용 (이 모듈은 SKILL 문서를 자동 갱신하지 않음)

## Step B. 비개발자 톤 재구성

- **기술 용어 일반화**
  - `incentive_t` → "인센 관리 데이터"
  - `tmcv.pov_idx 컬럼 DROP` → "수당 데이터의 옛 연결고리 정리"
  - `UNIQUE KEY 재정의` → "중복 방지 규칙 재설정"
  - `cron` → "자동 작업"
  - `commit/push/배포 흐름` → 노출하지 않거나 "운영 반영" 으로만
- **"왜/효과" 중심**: 코드 위치가 아니라 사용자에게 어떤 영향이 있는지
- **테마/진행도 명시**: 각 그룹 헤더 `"{테마명}: {진행도} ({일정})"` 형식 필수
- **사용자 검증 사항**: 별도 섹션 없이 본문에 자연스럽게 녹임
- **기술 식별자 노출 금지**: commit hash / 파일 경로 / 함수명 / SQL 컬럼명
- **이모지 절대 금지** — 텍스트만 (카톡/메일/SMS 전송 호환)

## Step C. 출력 형식

```text
안녕하세요. {{오전/오후}} 개발 진행상황 공유드립니다.

[개발 진행상황 공유 – MM/DD {{오전/오후}}]

{{테마명 1}}: {{진행도}} ({{일정}})

■ {{세부 작업명 1}}
{{1~2줄 친절한 설명. 어떤 화면/기능에 어떤 변화가 있는지}}

■ {{세부 작업명 2}}
{{설명}}

{{테마명 2}}: {{진행도}} ({{일정}})

■ {{세부 작업명}}
{{설명}}

기타 개선 및 안정화

■ {{REFACTOR_0427 외 작업 / 긴급 픽스 / 예정 정리 등}}
{{설명}}
```

원칙:
- 마크다운 헤더(`#`, `##`) 금지 — 카톡/메일에서 깨짐
- 굵게/이탤릭 자제
- 항목 글머리표는 `■`
- 시간대(오전/오후)는 인자 또는 항목 시간으로 추정 (`meta.ampm` 우선)
- 작업이 적으면 정직하게 "유지보수 작업 위주" 로 표기
- 작업이 많으면 핵심 3~5개로 요약하고 나머지는 "그 외 자잘한 정리 N건" 으로
- 고객에게 보내는 글 — 존댓말 / 친절 / 군더더기 없이

## Step D. 저장 + 화면 출력

1. 저장 경로 결정:
   - 프로젝트에 `worklog/` 개념이 있으면 → `worklog/customer/{date}.md`
   - 없으면 → `./{date}-progress-share.md`
   - 오전/오후 분리 시 `{date}-am.md` / `{date}-pm.md`
2. 폴더 없으면 생성 후 저장 (이미 있으면 덮어쓰기)
3. 동일 내용을 화면에도 출력
4. 마지막 한 줄 안내: "복사해서 고객에게 전달 가능. 추가 정리가 필요하면 알려주세요."

## 주의사항

- 소스가 비거나 일부 누락돼도 가능한 정보(세션 맥락 + git log + 변경 영역)로 의미 있는 보고서 생성
- 사람 손 커밋과 자동 커밋이 섞이면 사람 손 커밋 제목을 더 신뢰
- 테마 매핑 모호 시 "기타 개선 및 안정화" — 임의 추정 금지
- 이 모듈은 어떤 SKILL/계획 문서도 자동 수정하지 않는다 (읽기 전용 참조)
