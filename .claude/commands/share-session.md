# 세션/레퍼런스 기반 진행상황 공유본 생성 커맨드

워크로그가 **없거나 아직 안 쌓인 시점**에, 현재 세션 작업 내용이나 임의 레퍼런스를
비개발자(고객) 친화 톤의 진행상황 공유본으로 재구성한다.
**플래그를 외워 칠 필요 없이, 질문 인터페이스로 소스를 고른다.**

> 포맷·테마매핑·저장 규칙은 공통 모듈 [`_shared/customer-report-format.md`](_shared/customer-report-format.md) 가 단일 출처(SSOT)다.
> 이 커맨드는 **소스를 질문으로 받아 정규화**해서 그 모듈에 넘기는 역할만 한다.
> 워크로그 파일 기반 정리는 `/share-worklog` 를 쓴다.

> **사용 예시:**
> - `/share-session` — 질문으로 소스 선택 (오늘)
> - `/share-session 어제` — 날짜만 지정, 소스는 질문으로
> - `/share-session 2026-05-19 오후` — 날짜·시간대 지정

## 동작 절차

### Step 1. 날짜/시간대 결정
- `$ARGUMENTS` 파싱: 비어있으면 오늘(`date +%Y-%m-%d`). "어제/오늘/그저께" 변환. `YYYY-MM-DD` 그대로. → `$DATE`
- "오전/오후" 토큰 있으면 `meta.ampm` 반영

### Step 2. 소스 선택 — AskUserQuestion (필수)

`AskUserQuestion` 으로 **레퍼런스 소스를 질문**한다 (플래그 입력 대체). 질문 1개, 단일선택:

- 질문: "공유본을 어떤 내용으로 만들까요?"
- 헤더: "소스"
- 선택지:
  1. **이번 세션 작업** — 지금까지 이 대화에서 수행/보고한 작업을 정리
  2. **파일 레퍼런스** — 정리 메모/문서 경로를 받아 그 내용으로 정리
  3. **git 이력만** — 해당 날짜 커밋·변경 파일만으로 정리
  4. **직접 붙여넣기** — 사용자가 제공할 텍스트로 정리

선택 결과별 후속:
- "이번 세션 작업" → 현재 대화 맥락에서 이번 기간 작업을 항목화 (추가 입력 불요)
- "파일 레퍼런스" → 후속 질문 또는 사용자 입력으로 경로 1개 수령 → 읽어서 소스화
- "git 이력만" → Step 3 git 수집 결과만 소스로
- "직접 붙여넣기" → 사용자가 붙여넣을 텍스트를 소스로 (붙여넣기 요청 후 대기)

> 사용자가 질문에서 "Other" 로 경로/텍스트를 바로 줄 수도 있다. 그 경우 추가 질문 없이 그것을 소스로 사용.

### Step 3. git 보강 (항상 병행)
```bash
git log --since="$DATE 00:00" --until="$DATE 23:59" --pretty=format:"%h | %ci | %s"
git log --since="$DATE 00:00" --until="$DATE 23:59" --name-only --pretty=format: | sort -u | grep -v '^$'
```
- 자동 커밋(`*(auto):`)은 제목만 참고, 사람 손 커밋 제목은 그대로 신뢰
- 변경 파일 영역 그룹화: `api/lib/pages/assets/layouts`→"운영 시스템", `cron/`→"자동 작업", `sql/`→"DB 변경", `skill/QA`→"문서/계획", `scripts/.claude/CLAUDE.md`→"내부 도구/설정", `worklog/`→집계 제외
- git 레포가 아니면 이 단계 생략(선택 소스만으로 진행)

### Step 4. 정규화
선택 소스(+git 보강)를 공통 모듈 입력 계약(`{time, summary, areas}[] + meta`)으로 변환.
`meta.source` 에 실제 사용 소스 기록(session / ref:<경로> / git / paste).
소스도 git 도 비면 "정리할 작업 내역이 없습니다." 출력 후 종료.

### Step 5. 공통 모듈 적용
[`_shared/customer-report-format.md`](_shared/customer-report-format.md) 의
Step A(테마/진행도 매핑) → B(비개발자 톤) → C(출력 형식) → D(저장+출력) 를 **그대로 따른다.**
포맷/원칙을 여기서 중복 기술하지 않는다.

## 주의사항
- 소스는 **반드시 질문으로** 받는다 (`--ref` 같은 플래그 도입 금지 — 팀 사용성 우선).
- 레퍼런스가 기술 메모여도 출력은 비개발자 톤으로 변환 (원문 그대로 붙여넣기 금지).
- 책임은 **소스 정규화**까지. 톤/형식/저장은 공통 모듈이 결정한다.
- 공통 모듈 규칙(이모지 금지, 마크다운 헤더 금지, `■` 글머리표, 식별자 비노출) 준수.
